# 🚀 IM-Net: Anticipatory Meta-Control of Coupled Gradient Flows

> Official PyTorch and numerical implementation of the paper
> *Anticipatory Meta-Control of Coupled Gradient Flows: Resolving Magnitude Dominance and Deadlock in Multi-Objective Dynamical Systems*

## 📖 Introduction

> This repository contains the official implementation and numerical simulation code for **IM-Net**, an anticipatory meta-controller for stabilizing multi-objective dynamical systems.

>Unlike reactive gradient-surgery methods (e.g., PCGrad) that assume directional conflict, this work identifies **Magnitude Dominance** as the primary destabilizing pathology in natural learning landscapes: auxiliary gradient fields can be \(44.5\times\) to \(145.4\times\) larger than the primary field while remaining nearly orthogonal. IM-Net treats the optimization trajectory as a singularly perturbed continuous flow and uses a receding-horizon virtual probe with Lyapunov-guided dissipation to maintain asymptotic stability.

>The repository reproduces:

- CCO Duffing-oscillator simulations and bifurcation/MLE analysis (Section 4; Fig. 5 and Fig. 6)
- Gradient magnitude-dominance diagnostics (Section 5.1; Fig. 7)
- Main multi-task comparison on Yelp and Amazon (Section 5.2; Table 2)
- Over-intervention trap experiment (Section 5.3; Fig. 8)
- Extreme adversarial deadlock stress test (Section 5.4; Fig. 9)

## 📁 Dataset Preparation

⚠️ **Important for Reproduction:** In accordance with Section 5.2 of the manuscript, our reproduction code for IM-Net (and all meta-learning baselines) strictly reserves 10% of the training edges as a meta-validation set to compute the look-ahead gradient. In contrast, standard reactive baselines (PCGrad, MGDA, etc.) train on 100% of the training data, **as these methods do not require an auxiliary meta-validation split for gradient computation**. This protocol difference accounts for the minor nominal accuracy trade-off discussed in the paper.

> Place the processed bipartite-network datasets under data/:

```text
IM-Net/
│── data/
│   ├── amazon_books_processedDataV3/
│   └── yelp_processed_for_meta/
```

**Note for Reviewers: The pre-processed datasets are archived at Figshare: https://doi.org/10.6084/m9.figshare.32298051.**
The synthetic adversarial datasets used in the deadlock stress test are generated by
experiments/05_stress_test.sh; Intermediate files are written to results_reproduction/stress_test/; the final summary is written to results_reproduction/fig9_stress_test.csv.

### Reproduction Guide

All reproduction scripts write raw CSV data into results_reproduction/. Final figures are generated from those CSV files by experiments/06_plotting_figures.py.

### 🏆 1. CCO simulation: Section 4, Fig. 5 and Fig. 6

> Reproduce the coupled Duffing-oscillator phase portraits, synchronization trajectories, bifurcation diagram, and maximal Lyapunov exponent (MLE) crossing.

```bash
python experiments/01_cco_simulation.py 
```
Outputs default to results_reproduction/ and cco_figures/; override with REPRO_DIR=<dir> environment variable.

> Outputs:

> *results_reproduction/fig5_cco_phase.csv — phase-space and synchronization trajectories for Fig. 5

> *results_reproduction/fig6_cco_bifurcation.csv — order-parameter bifurcation data for Fig. 6

> *results_reproduction/fig6_cco_mle.csv — MLE versus coupling strength for Fig. 6

> *results_reproduction/table_s1_cco_params.csv — CCO parameters for Table S1

> Important: Fig. 6 in the final manuscript must contain both the bifurcation/order-parameter panel and the MLE panel. Use fig6_cco_bifurcation.csv and fig6_cco_mle.csv together; do not plot only one panel.


### 🔬 2. Gradient magnitude-dominance diagnostics: Section 5.1, Fig. 7


```bash
python experiments/02_grad_diagnostics.py \
  --dataset yelp \
  --data_path ./data/yelp_processed_for_meta \
  --output results_reproduction/fig7_grad_imbalance_yelp.csv

python experiments/02_grad_diagnostics.py \
  --dataset amazon \
  --data_path ./data/amazon_books_processedDataV3 \
  --output results_reproduction/fig7_grad_imbalance_amazon.csv

# (Optional) Fig.7 third bar: Yelp with synthetic anti-parallel conflict c=1.0
python experiments/02_grad_diagnostics.py \
  --dataset yelp \
  --data_path ./data/yelp_processed_for_meta \
  --simulation --conflict_scale 1.0
```
> Outputs cosine similarity and gradient-norm ratio statistics for Fig. 7.

> The third command writes results_reproduction/fig7_grad_imbalance_yelp_sim.csv (default _sim suffix); if it is missing, 06_plotting_figures.py will render Fig.7 with only two bars.

### ⏱️ 3. Main comparison: Section 5.2, Table 2

> **Note for Reviewers:** If you run `bash experiments/03_main_experiments.sh` from scratch, the full 12-run grid (Yelp 400 epochs + Amazon 200 epochs) will take approximately **50–60 GPU hours** on a single NVIDIA A40. For a quick smoke test to verify the pipeline without waiting for convergence, run `EPOCHS=5 bash experiments/03_main_experiments.sh`.

> Run all Table 2 baselines and IM-Net:

```bash
bash experiments/03_main_experiments.sh
```
Override paths via env vars, e.g. OUT_CSV=... DATA_YELP=... bash experiments/03_main_experiments.sh.

> The script must include the following six rows:

```markdown
| Regime | Strategy |
|---|---|
| Reference upper bound | Single-Task |
| Multi-task control | Fixed-Weights |
| Multi-task control | GradNorm |
| Multi-task control | PCGrad |
| Multi-task control | MGDA |
| Multi-task control | IM-Net |
```

> For manual runs, the entry point is:

```text
--mode single     # Single-Task upper bound
--mode fixed_weights   # Fixed-Weights
--mode gradnorm   # GradNorm
--mode pcgrad     # PCGrad
--mode mgda       # MGDA
--mode meta       # IM-Net
```
> Run the same grid for Amazon:

```bash
python core/main_gpu.py \
  --dataset amazon \
  --data_path ./data/amazon_books_processedDataV3 \
  --model_name LightGCN \
  --mode meta \
  --epochs 200
```

> Run the same grid for Yelp:

```bash
python core/main_gpu.py \
  --dataset yelp \
  --data_path ./data/yelp_processed_for_meta \
  --model_name LightGCN \
  --mode meta \
  --epochs 400
```

> To reproduce any baseline, replace `--mode meta` in the Yelp/Amazon commands above with one of `single`, `fixed`, `gradnorm`, `pcgrad`, `mgda`.

> **Hyperparameters:** method-specific values used in the paper are set inside
experiments/03_main_experiments.sh. Before final submission, keep these values synchronized with the final hyperparameter table in the manuscript/Supplementary Material.

## 🔬 Reproducibility Notes
> `core/main_gpu.py` accepts `--seed`; the three shell scripts pass it through. `experiments/01_cco_simulation.py` and `experiments/02_grad_diagnostics.py` use fixed seeds internally (`torch.manual_seed(0)` / `np.random.seed(0)`) for deterministic output.

> Table 2 must be generated from table2_main_results.csv; do not transcribe values manually from console output.

> Fig. 6 must use both fig6_cco_bifurcation.csv and fig6_cco_mle.csv. A single-panel order-parameter plot is not sufficient for the manuscript.

> Fig. 7 must report both cosine similarity and magnitude ratio $\rho = \lVert g_{\mathrm{aux}} \rVert / \lVert g_{\mathrm{main}} \rVert$.

> Fig. 8 must save both Recall@20 and total loss; the over-intervention claim depends on the loss spike and the plateau.

> Fig. 9 must save per-conflict-scale results for IM-Net, PCGrad, MGDA, and Fixed-Weights.

> Record GPU model, CUDA version, PyTorch version, and wall-clock time per epoch in the training logs.

> Single-seed log policy (repository-size constraint). experiments/03_main_experiments.sh runs one seed per invocation (SEED, default 2026) across both datasets and all six strategies, writing one log per (dataset, strategy) pair to results_reproduction/training_logs/table2_<dataset>_<strategy>_s<seed>.log. To keep the anonymous snapshot lightweight, only the logs of a single seed (seed = 2026) are archived; the remaining seeds' logs are not shipped. The archived logs document the exact per-epoch log format and the --seed / epoch-wall-clock record path; they are not the numerical source of Table 2 or Fig. 7–9. Table 2 values are produced by this script for the archived seed and saved to table2_main_results.csv (single-seed results; if the manuscript reports multi-seed mean ± std, that aggregate is obtained by running the same script with different SEED= values and aggregating the per-seed CSVs, and is not reproduced by the single archived CSV). Figs. 5–7 are deterministic fixed-seed outputs of 01_cco_simulation.py / 02_grad_diagnostics.py and require no multi-seed rerun; Figs. 8–9 follow the same single-seed protocol. The remaining seeds can be regenerated by re-running experiments/03_main_experiments.sh with different SEED= values (the script passes --seed through to core/main_gpu.py).
